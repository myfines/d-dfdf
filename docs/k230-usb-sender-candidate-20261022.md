# K230 独占 CDC 发送候选与运行步骤（未部署）

2026-10-22。针对 FPGA 主机候选 `f3a1e2f` 的接口准备，基线为[实测USB契约](k230-usb-interface-contract-20261021.md)及既有12字节协议。本阶段只写电脑仓库文件，没有打开硬件、执行K230脚本、写SD卡、改固件、下载FPGA或触碰Flash。其他聊天的SRAM操作不计为本阶段验证。

## 交付文件

- 发送逻辑：`k230/usb_gesture_sender.py`。
- 单文件构建：`python scripts/build-k230-usb-sender.py`。
- 可部署候选：`build/k230/usb_gesture_sender_standalone.py`，7619字节，SHA256 `18da9ffff3506edfdf45b7dda3d6f6f955c45deb1daa7289bf3666972774df8d`。
- 待审阅开机入口：`k230/usb_gesture_launcher.example.py`。**这只是电脑文件，未写入板上main.py。**
- 测试与构建记录：`logs/20261022-k230-sender/`。

单文件候选由既有编码器、新鲜度映射及发送逻辑组合生成，运行时不依赖另行上传编码器模块；仍依赖板上既有V2、官方关键点源码、库和模型。它先核对`/sdcard/pinch_preview_v2.py`的已知SHA256，再复用其LCD预览，避免悄悄适配未知版本。

## 与临时探针的区别

该候选没有`BINARY_TEST_BEGIN/END`、统计打印、REPL输入处理或USBDBG请求，正常模式不在有限包数后返回REPL。通过`usb.Serial('/dev/ttyGS0')`直接写入原协议bytes，未修改USB描述符。

屏幕继续显示关键点和捏合量。发送端只接受原始检测置信度**至少0.60**的新鲜单手TRACK；低于门限时发`valid=0`及三个零参数，并把原本TRACK的屏幕结果标为`USB LOW CONF`。不会把0.599四舍五入为60后放行，也不会把跟踪算法内部替代的置信度当原始检测值。FPGA门限保持60不变。

NO HAND、MULTI HAND、BAD GEOMETRY、LOW CONF、WARMUP、任何HOLD和超过150ms的结果均无效。坐标/捏合映射保持上一轮约定，捏合仍需校准。

发送线程目标周期50ms，过晚则重新安排，不突发补发历史数据。上一版相似结构的实际有手速率约7.49Hz；**新候选未经板上运行，不能宣称已解决20Hz问题**。处理部分写入和EAGAIN；25ms软件等待限额不保证底层阻塞write一定能被中断。write返回长度不等于USB主机确认收到。

Python stdout/stderr使用静默IOBase流，V2命名空间print也被抑制。新静默路径及新常驻程序尚未经过固件实测；原生驱动的printf可能绕过Python静默流，尤其初始化、故障和复位期间。因此不能承诺任意故障下线缆永远只有12字节包；主机字节解析必须保留找包头和CRC恢复。原生异常会否影响有效流需在电脑验包时继续检查。

致命错误时停止发送，留给FPGA既有250ms租约释放；错误信息仅留在RAM的`LAST_USB_ERROR`，不打印或写SD日志。默认静默停驻，避免异常后REPL提示符混入。停驻后以复位/断电恢复；不要在传包时连接IDE。尚未实测此固件上静默流、停驻、DTR重连及USB reset恢复。

## 接线切换的前提

**K230只有一根USB供电线时，从电脑换到Dock会断电，RAM程序不能跨这次换线保留。** 当前SD main仍为V2文本预览；现在直接换线不会启动这个新发送器。现有有界RAM探针成功不能替代开机入口部署。

本轮约定只准备/检查，因此不执行部署。后续获得相应部署指令后，顺序应为：

1. 电脑直连，IDE退出；核对目标1209:ABD1和当前main/boot、模型及已有备份。另存当前main备份，不能覆盖电赛和先前入口备份。
2. 把单文件候选另存为`/sdcard/usb_gesture_sender_standalone.py`，逐字节回读校验。先保持旧main不变，用独占普通CDC/raw REPL做候选运行验包，禁止IDE Run/USBDBG与二进制同时使用。先核验无效零心跳，再核验置信度>=60的真实手势；统计序号、CRC、噪声、速率及断流恢复。
3. 候选通过后，才用已审阅的启动入口切换main，并保留可恢复备份。先在电脑USB主机上做真正断电开机验包；若启动日志混入或没有连续有效数据，先恢复旧main排查，不把打印当传包成功。
4. 此后再把USB从电脑换到Dock OTG，K230重新上电从SD启动发送器；不要为此重启/RCFG Dock，否则SRAM候选会丢失并恢复Flash中的旧E023。Dock供电条件仍按既有方案核验；不增加第二路K230 5V。
5. FPGA侧先看健康报告CDC ready位，再看有效手势位；CDC ready=1不代表已收到CRC正确的应用包。门限不足时active=0是正确行为，不能为过验收虚增confidence或降低门限。
6. 若要回电脑IDE预览，先断开Dock，仅把K230接电脑，并进入独立维护流程停止发送、恢复保存的旧main；确认无二进制发送后才能恢复IDE调试。不要直接在正发送的81 IN上混入USBDBG。

上述是待执行步骤，不是已发生的硬件操作。USB HS host的实际枚举、SET_LINE_CODING/DTR控制、总线复位及本候选收包仍待联合验证。
