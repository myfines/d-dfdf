# UART同步发送修正候选

本候选替代旧UART后台线程方案。尚未部署；本轮没有访问设备、修改FPGA/Android、V2原文件或开机入口。

代码证据：原V2获取阈值0.30、维持0.18，而旧发送器另加原始分数0.60门限；骨架绘制仅依赖单手存在，不代表发送有效。旧发送线程还会在更新之间重复旧状态，并施加发布后150ms时效。以上可解释显示与输出不同步，但尚未实机确认各因素占比。

现每次原PinchTracker.update返回后同步发一个12字节包，无后台线程、20Hz定时器或旧状态重放。只有当前TRACK且valid、映射有效、真实原始分数>=0.18才发送有效参数；获取0.30及几何判定仍由原tracker负责。HOLD、WARMUP、无手、多手、无效几何立即发valid=0及零参数。真实分数按协议转换百分整数，不放大、不用tracker内部替代分数；0.1799不能因四舍五入至18而放行。屏幕返回原result，不改写TRACK为UART LOW CONF。慢帧逻辑保持原样。

UART1 115200 8N1，IO9 TX；固件要求同时将IO10配置UART1_RXD输入，外部IO10仍不接。沿用有界25ms部分写入与错误停止；正常一包约1.04ms，发送耗时仍可能进入下一帧dt，需实测。发送频率随识别帧率变化，不承诺20Hz。发送停止依赖FPGA250ms失联释放；无效帧立即释放。FPGA接收门限必须同步由60改为18，由FPGA侧单独处理；旧60接收器仍会拒绝低分包。

验证：先写测试得到FrameSender缺失失败，再实现；全套32项通过及py_compile通过。新增回归使用真实V2 tracker跨0.2999/0.30/0.18/0.1799阈值，核对HOLD等清零、原始分数、屏幕result不变、每次更新只发一包、无后台线程和旧PacketState；现有部分写入/CRC/IO10输入兼容测试保留。日志logs/20261022-k230-uart-sync/。主机测试不能代替实际串口CRC采集和手势连续性验收。
