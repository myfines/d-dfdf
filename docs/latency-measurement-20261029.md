# 延迟测量口径与当前证据

## FAQ原文能确认什么

用户提供两份群FAQ副本中，第73条问题是：

> 赛题2题目中“控制信号到音频输出总延迟 ≤10ms”需要把“传感器产生数据 → 接口读取 → FPGA 判定/滤波 → 触发音高”的整个输入链路也算进去吗？

答复只有：

> 看技术相关问题103

第74条“控制信号指物理信号（人的行为）还是传感器输出的电信号”没有答案。两份副本均不含技术103正文；不能编造其测量方法，也不能从空白答复推导豁免。已请求新版链接/正文，收到后补充引用并重新判定。

官网基础要求总延迟≤10ms，拓展要求≤5ms且确定性无抖动。下述是工程测量方案，**不是FAQ103原文**。

## 整机测量方案

1. 使用共同时间基准的双通道示波器/混合信号仪；CH1记录明确的控制输入，CH2记录DAC线性模拟输出。直接按键输入使用触点电信号；传感器方案另记录原始输出/总线，注明从哪个时刻开始。需要证明“人的动作”整链路时，增加同步光电参考/接触参考，不能省略摄像头采集与推理时间。
2. 主测采用干声、已稳定启用状态、固定音高/力度与预设，关混响/延迟/合唱；另测弦乐等慢起音预设。CH1上定义有效阈值边沿，CH2定义高于静音噪声的起音阈值及持续时间，保存阈值、静音基线、幅度和原始波形。不能仅盯着相位不定的首个过零点。
3. 用同一次采集的时间差`t_DAC_onset - t_control`；分别报告按键、光键、摇杆变化、K230路径，不以最快路径替代全部。至少跨不同音频帧相位重复触发，报告样本数、min/max、分位数、峰峰变化及仪器采样间隔。重复次数为本工程方法，不冒充官方规定。
4. 同时采LRCK，直接量相邻同向边沿周期求实际DAC输出采样率。46,875Hz是HDL设计值；电脑RAW48kHz是录音输入格式，两者不能互证。吞吐量声明须结合同配置32音录音/谱峰与RTL状态。
5. 检查探头量程、3.3V信号和共地；DAC仅测模拟线性输出，不直接连音箱功率输出到电脑/逻辑分析仪。逻辑分析仪测I2S只得到数字输出，必须明确排除DAC模拟延迟。

USB串口日志、电脑发送命令与录音时间戳、APK网络往返时间都不共用硬件时间基准；不能拿它们直接宣称≤10ms。手机普通视频帧率不足以精确验收5ms/10ms。当前PC录音的一次discontinuity也不能用来推定FPGA抖动。

## 本轮已补：控制输入至I2S数字仿真

[报告](../firmware/e028-extension/docs/e045-final-audit/report.json)与[原始结果](../firmware/e028-extension/docs/e045-final-audit/digital-latency.txt)。生产core的按键同步/64帧消抖/路由/合成/效果/I2S均未旁路；测量起点为仿真板载按键引脚跳变，终点为从I2S位流重组完成首个非零左声道16bit字。四音色×四种输入相位共16场景，27MHz：

- 首个非零完整I2S字：1.444667–1.460556ms。
- 绝对样本≥32的固定数字幅度阈值：最慢1.844556ms（弦乐）。此阈值是工程观察值，不是官方听觉阈值。
- 覆盖相位引起的首样本变化约15.889µs；并非“零抖动”。一帧设计周期约21.333µs，异步输入量化必须解释。

为隔离正常演奏阶段，仿真采用SAFE_STARTUP=0、测量前略过1秒启用保护，并指定音色，关闭UI/光键/手势模块、LINK_MODE=1；这些配置用于隔离按键演奏通路，不代表生产热点负载压力场景。解码结果逐字对照I2S模块锁存的左声道字；没有模拟传感器机械/采集、DAC模拟或声传播。不能把本报告标记为基础≤10ms或拓展≤5ms整机通过。

初版测试夹具误将WS变化时承载的上一声道LSB丢弃，造成“no I2S output”；已修正夹具为按标准I2S的一拍延迟及完整16bit字解码。生产RTL没有因此改动。
