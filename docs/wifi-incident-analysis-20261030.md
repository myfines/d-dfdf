# ESP热点丢失：记录回查与原因排序

本次仅回查记录、源码和公开资料，不改变固件或接线。用户补充：期间曾拔掉FPGA供电，故障时模块感觉不热；何时断电、ESP是否同路完全失电、线是否移动没有同步记录。热感不是温度或电流测量。

## 已知事实

1. 音频探针audio_delivery_probe不运行ESP初始化，ESP_TX高阻；测试期间不能要求热点被创建。但探针没有ESP电源/EN/RST控制，也没有更改ESP固件。
2. 正式E049恢复后需重新启用；用户确认OLED/光键正常但热点不存在。USB UART旁路ESP_RX监听60秒0字节，电脑扫描也未见SSID。0字节只证明FPGA端未收到，不能独自证明ESP没有发出或未供电。
3. E051保留正式输入控制，仅换观测UART，不能仅因使用探针就断言破坏热点。
4. E052每2秒发AT，累计72字节TX/108字节RX、收到OK；E053使用未改正式AT初始化器，114字节TX/47字节RX、六命令完成、ready且无超时，随后扫描出现热点。结束均恢复E049/6020，后续真实手机测试通过。不能由恢复倒推最初原因。

## 当前推测（不是定论）

优先怀疑ESP局部供电/接触/EN-RST启动状态异常，或者断电与重新配置之间的启动状态问题。原因是OLED及光键工作时ESP完全无应答，随后最小UART恢复应答，原初始化器也能成功，永久程序/引脚错误的解释较弱。VCC/GND/EN/RST接触会影响启动；仅UART接触异常则主要影响AT初始化，若AP尚未配置也可能表现为没有热点。没有电压波形或线缆动作记录，无法在这些候选中锁定一个。

正式初始化器在未ready时具有超时重试（27MHz下启动等待约2秒、单命令等待约1秒），所以普通“少等了一会儿”不是充分解释。ready后的空闲状态没有定期AT健康探测；依靠识别ESP发来的ready行重新初始化。ESP静默掉线或复位通知未被正确收到时，存在不能主动发现的恢复边界。这是源码观察到的可改进点，不是本次根因已经复现。

音频探针不运行Wi-Fi可以解释最早一段无热点，但不能完整解释正式版重新启用后持续无应答。FPGA断电后SRAM探针不能继续运行；如果板卡完整从Flash启动，运行的应是E049。只拔FPGA供电是否也让ESP彻底失电，取决于实际供电，不可默认。

## 蓝灯和温度

常见ESP-01S蓝灯接GPIO2、低电平亮；ESP-01及兼容版本接法可能不同。未核实实物版本/原理图，不能把蓝灯偶闪当Wi-Fi心跳，也不能用不闪证明死机。运行时是否可感到发热受持续时间、射频负载、休眠、外壳等影响；不热只能作弱线索，不能判无电。

## 下次出现时的判别证据

先保留故障状态，记录SSID扫描与原始UART；若有仪表，在ESP模块引脚处测VCC、EN、RST，而非只测电源出口。随后用已验证AT探针确认收发：电压/使能异常优先查供电接触；电压正常但无AT回复再查启动状态/串口；AT正常但无SSID则查AP配置及初始化。避免一上来重插或重下载导致证据消失。没有故障复现时不为猜测改线或重刷ESP。
