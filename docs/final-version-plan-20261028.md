# 总体整改与封版规划（2026-10-28）

状态：规划，尚未修改RTL、构建或烧录。基线E031；本轮覆盖K230的复测提交85729e2。目标是完成赛题基础要求，并使现有硬件能实现的扩展都有可复现证据。以下数值门槛除官方延迟/规模/维度数量外，均为我们拟定的工程验收目标，不冒充官方评分阈值。

## 2. 阶段A：先修两个已复现缺陷（候选E032）

### A1. 延迟反馈、初始化和增益

- 先恢复可用RTL仿真环境，复现现有负半周反馈算式。上次Icarus探针未跑通，signed问题仍是候选原因；只有失败测试与修复后通过配对，才升级为确认根因。
- 所有反馈乘法、移位、相加显式定义signed与中间位宽，先扩位后运算，在写回/最终输出处舍入和饱和；计数饱和事件，而非靠饱和掩盖不稳定反馈。
- 明确延迟RAM上电有效性：写零扫描或有效深度屏蔽，不依赖未初始化BSRAM内容。复位、关闭、再开启的尾音保留/清空采用明确规则；清空期间湿声禁止，避免重新打开复活旧异常数据。保持同步RAM推断，不给大数组加难综合的整体复位。
- 干声增益在效果开关前后一致；湿声系数、反馈系数和总输出余量明确，反馈幅值严格小于1。切换时短渐变只用于消除跳变，不能把渐变等待加入干声流水线。
- 回归：正负脉冲对称、零输入、最大输入、32音、模式开关、重新启用、复位。初始反馈3/8时，目标脉冲后1秒内接近数字量化底（例如±1LSB），不得增长或持续大幅自激；任意合法参数不溢出/绕回。
- 实物干/湿A-B-A同电平录音：无削波、无异常持续音；有条件关闭录音AGC或改线路输入。仅降低音量不能作为根因修复。

### A2. 音高映射

- 将线性ratio替换为指数音程映射：r=2^(semitones/12)，bend中心8192，上下边界分别精确映射−2/+2半音。正负端长度分别8192/8191，端点单独处理。
- 拟用257点定点查表+线性插值，离线生成常数与误差报告，保留共享乘法器和576周期预算。先评估ROM布局/时序，不盲目扩DSP。
- 颤音也在音分/音程域叠加后映射，避免改了弯音却留下非对称颤音；参数跨帧生效并短时平滑。
- 验收：中心恒为1，单调、正负对称；扫完整14位输入及32音，数字映射目标误差≤2音分，实录目标≤5音分（低音用更长窗口）。C4两端目标约233.082/293.665Hz；这两个音分门槛是自定质量目标。

阶段A不同时改OLED/网络/引脚；独立提交、先仿真再SRAM、通过后再考虑Flash，确保能定位回归来源。

## 3. 阶段B：补齐基础和演奏质量（候选E033）

- ADSR：新增明确的A/D/S/R运行参数，时间单位ms、S用归一化电平；按音符触发锁存对应声部参数，释放从当前包络开始。规定重触发、连奏、换音色对已发声声部的行为，避免共享参数串音。保留预设快捷恢复。
- 不破坏旧APK协议：新增带版本/长度/校验的扩展参数命令，旧V/T/M等继续兼容；解析、范围检查、影子寄存器、帧边界提交分离。WebMCP优先支持新参数；这不是强制重写现有ESP握手。
- 测试A长短、D长短、S高低、R长短，各变化一个量；从数字样本量化曲线/阶段时间，实录确认听感与无爆音。实时调参和声部独立性分别测。
- 音色先精修电钢琴/风琴两种，再完善弦乐/贝斯：谐波、滤波、ADSR共同形成差异；同音同力度做响度匹配和盲听，避免仅靠音量区分。
- 混音先选明确固定余量并验证32声部最坏峰值，必要时再做平滑补偿/软限幅；不采用随瞬时声部数突然跳变的归一化。记录数字峰值、限幅率、模拟输入削波，三者分开。
- 保持现有46.875k输出，除非测量或音质证明需换时钟；题目没有强制48k，临近封版不为数字好看改PLL。

## 4. 阶段C：三维表情、可视化与独立现场测试（候选E034）

- 路由清晰：光键选音/触发；摇杆X弯音、Y可选力度或亮度；K230捏合表情音量、高度可选亮度。必须能展示至少三种独立有效表情，不能把同一量重复命名计数。
- 远程/本地/手势显式选择，显示当前控制来源；源切换平滑，丢手恢复有界。单音力度在note-on锁存，全局表情独立，避免总音量被同时乘两次而造成曲线难控。
- WebMCP补设备已应用序号/参数快照、voice_count、手势有效、峰值/限幅计数、测试状态与错误原因。ACK仅表示接收，随后读回确认。序列测试有最长持续时间和finally停音。
- 显示布局：主界面突出音色/活动声部/控制源/音量；波形/频谱/李萨如/指引独立页面。音频生产快照，OLED消费最新帧，不逐像素等待音频，不把32点遥测误称音频录音。
- OLED验收真实画面：定频对应频谱区间、单音/和弦波形变化、音频停后图形衰减；帧率依据总线实测填写，不预先保证60fps。
- 纯脱机测试入口保留32音模式、按声部选择与暂停，LED曲目和OLED目标键一致；测试音必须可明确退出。Wi-Fi掉线不影响光键发声和曲目指引。

## 5. 阶段D：手机扩展与交付

- 在线曲谱：定义事件格式（音符、起止/时长、力度、速度），先解析与校验，再分块下载到FPGA事件存储；验证超长/损坏拒收、数量上限、曲目时钟及断网后运行。预置曲目不能冒称已实现下载。
- 自定义键位：手机编辑→FPGA确认→实际按键验证，保存/恢复行为明确；不仅重排手机画面。
- 录音回传：真实音频必须来自DAC采集。现板无已验证ADC上行链路，手机TRRS麦克风需匹配衰减/偏置与转接，不能直插当线路输入；电脑采集只能称电脑辅助录音。若新增USB音频采集器，先兼容性验证再采购，不让ESP-01S承担无ADC输入的凭空录音。
- 蓝牙：作为独立选项，若要求全扩展演示则补合适BLE-UART模块及真机配对；先核对模块协议/3.3V供电/额定电流。不将Wi-Fi已完成等同于BLE已完成。当前已做好的K230/UART和ESP路径保持可回滚。
- 页面网络只做控制和遥测，本地音频时序不依赖互联网；现场演示不依赖临时Cloudflare地址持续有效。

## 6. 验收、版本和封版门槛

每阶段：失败复现→数字参考/RTL回归→资源/时序（27MHz setup/hold通过）→SRAM短测→同条件实录→对照表更新。完整候选通过后，才Flash写入校验、全断电冷启动、重复演奏与脱机测试。

延迟要用双通道/同步采集：一路输入电平，一路DAC；记录测量探点、触发阈值、采样率、至少100次输入/输出事件。软件日志、USB录音开始时间、网络响应不作为10/5ms证据。基础本地路径与K230视觉路径分别报告，不承诺摄像头模型满足5ms。用户已有示波器可先评估用途；不足时再借仪器，不先要求购硬件。

长时试验分级延长，先短时再15/30分钟；数字探针不等于芯片温度传感器。历史快速发热原因未查明，出现异常发热立即停机并保留现场。每轮保留安全可回滚镜像，不连续盲刷。

候选版本名E032/E033/E034为规划，未生成。E031/85729e2是本轮起点。Flash、源码、参数、APK/Web协议与测试记录一一对应；修订docs/current-release.md的旧E026描述应在新候选正式部署时进行，避免规划冒充发布。
