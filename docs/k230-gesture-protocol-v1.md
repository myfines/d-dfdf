# K230→FPGA 手势协议 V1（仿真候选）

2026-10-21。本阶段仅源码与仿真，板上E023、K230当前开机程序、引脚约束和接线均未改。不是USB主机实现，也不是整机已联调。

## 分层与数据包

K230 `gesture_protocol.py` 编码 → UART或未来USB字节传输 → `gesture_packet_rx.v` 校验 → active/pinch/y/confidence。`gesture_uart_rx.v`复用已有uart8n1，默认27MHz/234=115384.6 baud，目标115200/8N1；未来USB主机交付byte_valid/byte_data后可复用解析器，USB枚举、端点驱动和CanMV输出接口仍需单独实现。

包长固定12字节，整数大端：

| 字节 | 定义 |
|---|---|
| 0..1 | A5 5A同步头 |
| 2 | 版本01 |
| 3 | 序号0..255 |
| 4 | 00无有效手，01有效，其他保留并拒绝 |
| 5..6 | 捏合张开程度0..1000，0合拢、1000张开 |
| 7..8 | 手部纵向位置0..1000，0图像顶部、1000底部 |
| 9 | 检测置信度0..100（不是关键点精度保证） |
| 10..11 | CRC16-CCITT-FALSE，覆盖2..9，初值FFFF、多项式1021，无反射、无最终异或 |

CRC标准检查串123456789→29B1。当前K230预览百分比是临时范围；尚未校准成真实音量。上游应将单手、新鲜且有效的结果映射到0..1000；NO HAND、MULTI HAND、BAD GEOMETRY、过期HOLD发送valid=0及零值。不要把HOLD当新识别成功。手部y的提取和映射尚未接入当前识别循环。

建议每50ms发送一次（20Hz），即使无手也发送无效心跳；每包线上约1.04ms，不代表摄像头/识别/音频总延迟。当前仅提供可导入的编码函数，未自行初始化UART或改运行中的识别程序。

## 接收行为

- CRC、版本、保留位、范围都正确才产生update。低于60置信度或valid=0的合法新包会释放active并清参数，不触发音符。
- 序号采用模256前向窗口：差值1..127接受，0重复和128..255旧包拒绝。255→0正常。超过250ms未收到合法新包释放并允许发送端重新起始序号。合法但无手的包仍续租并更新序号；坏包、旧包、重复包不续租。
- 默认字节间隔超过20ms丢弃半包；重复A5可重新找同步头。CRC失败后重新搜索同步头，若新包头恰好落在已收坏包内部，可能损失后续一个包，但持续合法帧可恢复，250ms租约不因坏包延长。
- 不把包内容组合输出到音频；接收的参数只有完整校验后同一时钟提交。缺省/重置/失联active=0、参数0。后续音频集成必须用active选择本地值，不能把失联清零误当永久静音命令；还要加入参数平滑、优先级和硬件测试。
- 该序号仅用于链路新鲜度，不是加密认证。CRC能发现传输错误，不证明来源。

## 使用编码器（非实板部署）

```python
from gesture_protocol import encode
frame = encode(0, True, 750, 250, 95)
# 由已核验的传输层发送完整frame，例如 uart.write(frame)。
# 调用者检查返回写入长度，不把部分写入当整包成功。
# 每50ms递增序号：(seq + 1) & 255；丢手发 encode(seq, False, 0, 0, 0)。
```

## 仿真证据

`tb_gesture_link.sv`不是只向解析器灌字节，而是把Python独立生成、带CRC的数据包按起始位/8数据位/停止位送入UART串行线。覆盖同步噪声、截断及间隔恢复、CRC损坏、未知版本、越界、保留位、重复/旧包拒绝、序号回绕、丢手、低置信度、租约超时、发送端重启、坏停止位和重置。重复包持续到来也不能维持租约。

真实速率附加测试：接收234时钟/bit、发送235时钟/bit（约0.43%偏差）通过。该仿真使用缩短的租约/间隔计数加速，未实测引脚电平、线缆、物理时钟或摄像头延迟。

Python测试还检查标准CRC和12字节每一位翻转（96种）都被拒绝；原K230跟踪测试一同回归。完整RTL回归由instrument_io/run_tests.ps1生成共享向量后自动执行。日志见logs/20261021-gesture-*。
