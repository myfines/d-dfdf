# 板载按键与芯片到货前的音频工作

日期：2026-09-29。当前只做资料核对和开发安排；本节不下载码流、不操作 Flash。

## 引脚与现有程序

| 丝印 | FPGA 引脚 | `audio_keys` 状态 |
|---|---|---|
| S0 | T10 | 官方称复位脚；现有程序未使用。T10 还有 SSPI 双用途限制，暂不改作演奏键。 |
| S1 | T3 | `btn_n[0]`，C5 |
| S2 | T2 | `btn_n[1]`，D5 |
| S3 | D7 | `btn_n[2]`，E5 |
| S4 | C7 | `btn_n[3]`，G5；官方约束把它列为普通输入，用户观察到疑似“重启”，待实物排查。 |

依据：[Sipeed 官方约束](https://github.com/sipeed/TangPrimer-20K-example/blob/main/Litex/sipeed_tang_primer_20k/src/sipeed_tang_primer_20k.cst)以及[官方复位脚说明](https://github.com/sipeed/TangPrimer-20K-example#reset-pin)。当前版本按键逻辑是最低键优先的**单音**；四个键不等于四复音。

## S4 的一次低风险诊断

先确认当前 SRAM 程序仍在运行（心跳 LED 在闪）。只按 S4 一次，观察耳机是否出 G5、按键 LED 是否点亮、心跳 LED 是否持续；松开后按 S1，观察 C5 能否直接发声。不要把 S0 纳入这轮按键测试。

- 如果 S1 仍能发声，FPGA 程序仍在，优先核对按键丝印位置、S4 接触及 C7 输入，不把 S4 叫作复位键。
- 如果所有声音和心跳都消失，可能是 SRAM 配置丢失；结合 USB/电源状态、是否误按 S0 再定位。单凭用户看到灯重新闪烁，不能断定具体原因。
- 诊断时不写 Flash；若程序确已丢失，按已记录的 SHA256 核对后才重新下载 SRAM。

## 芯片到货前的工作顺序

1. 保留 S0 的复位用途，不为了凑第五键启用 T10 双用途。
2. 在现有 4 个键和 Dock 板载 PT8211 耳机口上，完成四个独立 DDS 声部、各自 ADSR 与限幅混音；当前最低键优先逻辑要改成允许同时按四键。
3. 先做 HDL 仿真和高云综合/时序核对，再用 SRAM 下载实测；逐一核对四音和弦、松开单键仅该音消失、其他音不中断。
4. 如 S4 的实物故障被确认，再把 C7 诊断和板外按键替代列为独立硬件问题；四声部引擎仍可在仿真与自动测试模式先验证。
5. MCP3008、摇杆和外接标准 I²S DAC 到货后才接线。当前 PT8211 用于音频开发，不把它的 LSBJ 接口冒充为最终 I²S 输出。
