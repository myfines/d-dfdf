## 2. 关键结果

### 2.1 32 声部

```text
tb_synth32: PASS synth32 voices=32 nonzero=11 max=1075 latency=1
tb_core:    32-voice stress: voices=32 sample=-488
```

`voice_count=32` 说明 32 个 gate 同时被引擎接纳；每个声部有独立相位/包络/力度状态。32 个半音同时发声会有拍频/相消，因此瞬时 sample 可能较小，这是信号本身，不是声部未运行。

### 2.2 音色与表情

```text
timbre 0 sum=3832436 peak=18162
timbre 1 sum=3387549 peak=18118
timbre 2 sum=934683  peak=4154
timbre 3 sum=7327206 peak=19108
expression peak=4559          (expression=64；满值峰值约 18k)
bend increment +/27116664 = 27116664/20825996   (1.302，约 ±2 半音)
PASS features timbres/expression/bend
```

Strings 的 500 帧能量较低，是因为它的起音时间为慢起音（attack_step=32，约 2048 帧到满），这是设计选择；不是静音。

### 2.3 效果器

```text
PASS fx chorus=1 delay=1 reverb=1 nonzero=100 max=10000
```

分别检查 `chorus_q`、`delay_q`、`rev1_q` 非零；FDN 反馈已从早期不稳定的 0.75/0.25 注入改为 0.5 交叉反馈 + 0.5 全通，长时间仿真不再饱和。

### 2.4 频谱

```text
band 0 = 19
band 7 = 105
band 8 = 109
PASS spectrum peak_band=8 level=109
```

1 kHz 正弦输入，峰值落在 858 Hz/1166 Hz 两个相邻 band，100 Hz band 只有 19。

### 2.5 OLED

```text
OLED online
PASS OLED UI bytes=3072
```

第二帧频谱 band0=0xFF（8 个像素全亮），第三帧指引 key5 在列 80 的字节为 0x7E。I2C 用简化 sink 模型 ACK，验证 1024 字节/帧的显存流。

### 2.6 延迟

```text
btn stable at 1355258 ns (frames=64)
gate bit28 at 1376592 ns (frames=65)
key->audio: 1408629 ns (1.409 ms)
PASS core latency=1408629 ns ads=13
```

按键去抖 64 帧（1.365 ms）+ 合成 1 帧 + I2S 1 帧 = 1.409 ms。小于 5 ms，且没有软件调度抖动。

## 4. 已知告警

- `synth32` 若干部位有“表达式位宽截断”警告（例如 `mix_sum` 饱和后的 16 位截取），均已用显式饱和/移位处理，属预期。
- `wifi_telemetry` 有旧有的 32 位索引截断警告，E027 即存在，不影响功能。
- `oled_ui` 的 `char_index` 7→5 位截断警告：列 0..127 除以 6 的最大值 21 落在 5 位内，安全。
- `gesture_uart_rx` 内部 `uart8n1` 的 `tx` 未连接（只收不发），属预期。
