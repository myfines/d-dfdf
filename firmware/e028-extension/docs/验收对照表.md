## 二、逐条结论

1. **32 复音并行引擎：代码/仿真完成。**
   不是“32 个固定频率测试库”：每个槽位有独立相位、独立包络、独立频率（C3–G5 半音表）、独立力度；渲染时共享乘法器但状态不共享。实物需用 App `MFFFFFFFF` 或 latch 累积 32 音复测。

2. **≥3 维表情：代码/仿真完成。**
   力度、弯音、颤音、亮度、震音、总表情均已接入音频路径；不是只改显示。弯音实测相位增量比 1.302（约 ±2 半音）。

3. **≥2 种音色：代码/仿真完成。**
   4 种音色的谐波结构和包络均不同；仿真能量差异明显。音色“像不像真实乐器”仍需人耳主观评价，不能仅凭 RTL 宣称达到专业音源水准。

4. **内部效果器：代码/仿真完成。**
   合唱/延迟/混响均为 FPGA 内部同步 BSRAM 延迟线与反馈网络，不依赖手机或外部 DSP；混响为 2 线 FDN，不是高密度专业混响。

5. **可视化：代码/仿真完成。**
   波形、16 段频谱、李萨如、演奏指引、状态共 5 屏；频谱来自真实后级音频，不是静态回放。OLED 全帧约 100 ms（100 kHz I2C），频谱计算每音频帧更新。

6. **LED 曲目指引：代码/仿真完成。**
   曲目在 FPGA 内部，断网/断手机仍可运行；4 颗板载 LED 只能粗分 4 组，具体键位看 OLED。不能宣称“8 灯一一对应”。

7. **BLE/App：代码完成，实物未配对。**
   FPGA 端 `LINK_MODE=1` 与 BLE-UART 透明模块兼容；Android BLE App 已提供源码与 APK。未在真实 BLE 模块上验证连接、MTU、断线重连。

8. **≤5 ms：仿真完成，实物未测。**
   仿真 1.409 ms（按键去抖 64 帧 = 1.365 ms + 合成 1 帧 + I2S 1 帧）。确定性来自固定帧同步和固定流水线，不依赖 CPU 调度。光键路径另有 ≤1 ms I2C 轮询，仍小于 5 ms，但需实物示波器确认。
